interviewQuestions:
  - prompt: How do you find a loop in an unfamiliar assembly listing?
    answer: >-
      Look for a conditional jump whose target label is above it: a backward
      branch. The instructions between the label and the jump are the loop
      body plus its exit test. Optimized code often tests the condition at the
      bottom and guards the first iteration with a separate check before the
      loop, so the source's `for` header is split across two places. The
      instructions that change the compared register tell you the induction
      variable, which may be a pointer rather than the source's index.
  - prompt: What does a compiler typically change in a simple loop between -O0 and -O2?
    answer: >-
      At -O0 every variable lives in a stack slot, so each use is a load and
      each update a store, which keeps the code easy to debug. At -O2
      variables stay in registers, an index can become a pointer that advances
      by the element size, the exit test moves to the bottom with a guard
      before the loop, and the loop may be unrolled or vectorized. The results
      are the same; the dynamic instruction count and the debugger's view of
      variables differ.
  - prompt: Why does a function push rbx before using it?
    answer: >-
      Under the System V x86-64 ABI, rbx is callee-saved: a function must
      return with the value its caller left there. A function that needs a
      value to survive its own calls keeps it in such a register, so it must
      save the caller's value first and restore it before returning. Argument
      and temporary registers such as rdi, rsi, rdx and rax are caller-saved,
      so any call may overwrite them.
    followUps:
      - Why must rsp be a multiple of 16 just before a call instruction?
  - prompt: How does a conditional jump decide whether to jump?
    answer: >-
      A preceding instruction such as `cmp` or `test` computes a result only
      for its flags: zero, sign, carry and overflow. The jump reads a
      combination of flags. Signed comparisons use sign and overflow, for
      example `jl` jumps when SF differs from OF; unsigned comparisons use the
      carry flag, for example `jb` jumps when CF is set. The same bits can
      therefore compare as less under one condition and greater under another.
  - prompt: How does a function call differ between x86-64 and ARM64?
    answer: >-
      On x86-64, `call` pushes the return address on the stack and `ret` pops
      it. On ARM64, `bl` puts the return address in the link register x30 and
      `ret` jumps to x30, so a function that calls another must first save x30,
      usually with the frame pointer in a single `stp`. Both ABIs pass the first
      arguments in registers and require a 16-byte aligned stack at calls.

## When the source is not enough

A profiler points at one line of C, `total += values[i]`, and the debugger says
`i` is "optimized out". A benchmark of that loop runs faster than seems
possible. Both questions are answered by the instructions the compiler actually
produced. You do not need to write assembly to read it: a listing is a small
number of patterns repeated.

Reading a listing is like reading a recipe translated into a language with a
tiny vocabulary: each step is simple, and the skill is recognizing which group
of steps makes up "knead the dough". The analogy stops at order: the compiler
may rearrange, merge or delete steps as long as the result is the same.

The [registers lesson](/learn/computer-architecture-execution/cpu-registers-and-instructions/)
read three instructions of a straight-line function. This page adds the two
things that make real code non-linear: **branches** and **calls**. Every listing
here is GCC 15.2's output for Linux x86-64, compiled and checked by the native
lab.

## Read the listing beside the source

Listings use AT&T syntax: `op source, destination`, a size suffix (`l` for 32
bits, `q` for 64), `%` before registers and `$` before constants.
`8(%rdi)` reads memory at rdi + 8, and `(%rdi,%rsi,4)` means rdi + rsi × 4.
Lines starting with a dot are assembler directives, such as alignment and
unwinding data; labels end with a colon.

The compiler kept the computation and changed its shape. There is no `i`:
`%rdi` itself walks through the array, 4 bytes per element, until it reaches an
end pointer computed once before the loop. That is why the debugger cannot
show `i`. The `endbr64` at the top marks a valid target for indirect branches,
a security feature; it does no arithmetic.

## Conditions are flags plus a jump

Comparisons do not produce a true or false value in a register. `cmp b, a`
computes a − b, and `test b, a` computes a AND b, only to set **flags**: ZF if
the result is zero, SF if its top bit is set, and CF and OF for unsigned carry
and signed overflow, the same conditions as in the
[binary lesson](/learn/computer-architecture-execution/binary-and-data-representation/).
The next conditional jump reads them:

<div className="table-scroll" tabIndex={0} role="region" aria-label="Conditional jumps and the flags they read">

| Jump  | Jumps when        | Meaning after `cmp b, a` |
| ----- | ----------------- | ------------------------ |
| `jne` | ZF = 0            | a ≠ b                    |
| `jl`  | SF ≠ OF           | a < b, signed            |
| `jle` | ZF = 1 or SF ≠ OF | a ≤ b, signed            |
| `jb`  | CF = 1            | a < b, unsigned          |

</div>

Signed and unsigned conditions read different flags from the same subtraction,
so the compiler picks the jump from the C types. In `sum_to`, `testl %esi, %esi`
followed by `jle` asks whether `count` is zero or negative, because `count` is a
signed `int`.

## A loop is a backward branch

A **basic block** is a run of instructions with one entry and one exit: control
enters at its first instruction and leaves at its last. Drawing blocks and the
jumps between them gives the function's **control-flow graph**. A jump to a
block above is a loop.

Both versions test `i < count` at the bottom of the loop, so each iteration
needs only one branch. -O0 reaches the test with an unconditional `jmp` the
first time; -O2 checks `count ≤ 0` once before entering. Before you step,
predict how many times `jne` jumps back for four values.

<AssemblyStepper client:visible listings={{ sumO0, sumO2, scaleO2 }} />

The same -O2 loop without JavaScript, for `values = {3, 5, 7, 9}` at 0x5000:

<div className="table-scroll" tabIndex={0} role="region" aria-label="The -O2 loop, iteration by iteration">

| Iteration | `addl (%rdi), %eax` | rdi after `addq $4` | `cmpq %rdx, %rdi` | `jne .L3`     |
| --------- | ------------------- | ------------------- | ----------------- | ------------- |
| 1         | eax = 3             | 0x5004              | 0x5004 ≠ 0x5010   | jumps         |
| 2         | eax = 8             | 0x5008              | 0x5008 ≠ 0x5010   | jumps         |
| 3         | eax = 15            | 0x500c              | 0x500c ≠ 0x5010   | jumps         |
| 4         | eax = 24            | 0x5010              | equal, ZF = 1     | falls through |

</div>

For this input -O2 executes 23 instructions and -O0 executes 58: -O0 loads `i`
and `total` from the stack and stores them back on every iteration. That is a
count of executed instructions in the model, not a timing.

## Calls follow the calling convention

`scale_sum` calls `sum_to`, which is compiled in a different file, so GCC
cannot see which registers `sum_to` uses. It relies only on the **System V
x86-64 calling convention**: the first integer arguments arrive in rdi, rsi and
rdx, an `int` result returns in eax, and rbx, rbp and r12–r15 are
**callee-saved**, so a function must return with the values its caller left
there. Every other general-purpose register may be overwritten by any call.

/>

In the stepper, choose `scale_sum` and watch the stack. `pushq %rbx` saves the
caller's rbx; `call` pushes the address of the `imull` that follows it and
jumps; `ret` in `sum_to` pops that address and resumes there. The push of rbx
also makes rsp a multiple of 16 at the `call`, as the ABI requires. The `@PLT`
suffix asks the linker to route the call through a table in case `sum_to` ends
up in a shared library; the [compilation lesson](/learn/computer-architecture-execution/compilation-and-execution/)
covers linking.

it afterwards, rather than in a callee-saved register.

<summary>Check after attempting</summary>

−2³¹ − 1 overflows: the 32-bit result is 0x7fffffff, so SF is 0 but OF is 1.
SF ≠ OF, so `jl` jumps, which is correct because −2³¹ is less than 1. For
`ja`, −1 is the pattern 0xffffffff, the largest unsigned value, so
0x7fffffff − 0xffffffff borrows: CF is 1 and `ja` does not jump.

## Two-minute recap

- AT&T syntax is `op source, destination`; ignore directives and find labels,
  jumps, calls and returns first.
- `cmp` and `test` only set flags; signed jumps read SF and OF, unsigned jumps
  read CF.
- A jump to a label above it is a loop; optimized loops usually test at the
  bottom after a guard.
- Arguments arrive in rdi, rsi, rdx; results return in rax; callee-saved
  registers must be restored, and rsp is 16-byte aligned at a call.
- -O2 keeps values in registers and may replace an index with a pointer, so
  source variables can disappear from the debugger.
