interviewQuestions:
  - prompt: When is the formula hit time plus miss rate times miss penalty useful?
    answer: >-
      It estimates the average latency of one access for a simplified cache
      model when the penalty is the additional time after the cache lookup has
      already been paid. The miss rate must describe the accesses entering that
      cache level. If the quoted miss latency already includes the lookup, use a
      weighted average instead to avoid double counting. Overlap, prefetching,
      queuing and multiple outstanding requests limit its ability to predict
      whole-program time.
  - prompt: An L2 cache misses half of its accesses. Is that a bad cache?
    answer: >-
      Not necessarily, because that rate is usually local: it counts only the
      accesses that already missed L1. If L1 misses 4% of loads, half of those is
      2% of all loads going on to the next level. What matters is how much time
      those 2% add to the average, which depends on the next level's latency.
      State whether a miss rate is local or global before comparing caches.
    followUps:
      - How would you compute the global miss rate of an L3 from three local rates?
  - prompt: Is a TLB miss the same as a data-cache miss or a page fault?
    answer: >-
      No, a TLB caches virtual-to-physical address translations, while a data
      cache holds data blocks. A TLB miss requires finding the translation, often
      through a hardware page-table walk, and the requested data can still be
      resident in a CPU cache. A page fault is a separate exceptional condition,
      such as a missing mapping or an access that violates permissions. It does
      not necessarily require reading a disk.
  - prompt: What is TLB reach, and why can larger pages help?
    answer: >-
      Reach, or coverage, is how much memory a TLB can translate without a miss:
      its entries times the page size. A program that touches more pages than
      the TLB holds in a short period takes TLB misses, and each one adds a
      page-table walk. Larger pages map more bytes per entry, so the same TLB
      covers far more memory, which suits large, randomly accessed data such as
      a database's. Whether it helps depends on the access pattern, so measure
      TLB misses before and after.

## A rare miss can dominate the time

A profile shows that only one load in ten misses the cache, and someone
concludes that memory hardly matters. If a hit takes 1 ns and a miss adds
50 ns, that one load in ten makes the average load take six times as long as a
hit. Hit rates alone cannot say whether a cache is good enough; the time each
miss adds decides it.

Think of a flight that boards on time on most days, but one day in ten is
delayed by an hour. The average delay is six minutes, all of it from the rare
bad day. The analogy stops at overlap: a processor can wait for several misses
at once and keep working meanwhile, so an average per access does not add up
to elapsed time the way delays add up over a year.

The [memory hierarchy lesson](/learn/computer-architecture-execution/memory-hierarchy-and-caches/)
traced which accesses hit and miss. This page prices them, first through the
cache levels and then through address translation. Every parameter here is an
illustrative model input, not a measurement of a processor.

## Average one access

Every access pays the cache's **hit time**, the time to look it up. A fraction
of accesses, the **miss rate**, then also pays the **miss penalty**: the
additional time to fetch the line from the next level. MIT's Computation
Structures lecture writes the average in exactly these terms:

**Average access time = hit time + miss rate × additional miss penalty.**

With a 1 ns hit time, a 10% miss rate and a 50 ns additional penalty, the
average is 1 + 0.1 × 50 = 6 ns. Check which kind of penalty a number is before
you use it. If 50 ns instead described the whole miss, lookup included, the
average is a weighted one: 0.9 × 1 + 0.1 × 50 = 5.9 ns. Adding the hit time to
a total would count the lookup twice.

## Nest the levels: local rates multiply

A miss in L1 does not go straight to memory; it looks in L2, which has its own
hit time and miss rate. So L1's miss penalty is the average time of an access
to L2, and the formula nests, one level inside the miss term of the level
above:

**Average = h₁ + m₁ × (h₂ + m₂ × memory time).**

Each mᵢ is a **local miss rate**: the fraction of the accesses that reach that
level and miss it. Multiplying the rates gives a **global** one: the share of
all loads that get that far.

<AccessTimeParts />

With L1 at 1 ns and 10% local misses, L2 at 4 ns and 25% local misses, and
memory at 80 ns, the average is 1 + 0.1 × (4 + 0.25 × 80) = 3.4 ns. Only 0.1 ×
0.25 = 2.5% of loads reach memory, yet they add 2 ns, more than every L1 hit
together. A local rate of 25% sounds poor until you see that it applies only to
the tenth of loads that missed L1.

The common mistake is to treat a local rate as global: reading the L2's 25% as
a quarter of all loads going to memory would add 20 ns instead of 2. The other
is to stop at the average. This model assumes every access waits for the one
before it. Independent loads, out-of-order execution, prefetching and queuing
change how averages turn into elapsed time, so the average is a price list,
not a stopwatch.

## Translation comes before the data

Programs use virtual addresses, so every access first needs its physical
address. A **TLB** (translation lookaside buffer) is a small hardware cache of
frequently used translations. On a **TLB hit** the translation is quick. On a **TLB
miss** the page table, which lives in memory, must be read: on x86 the hardware
**walks** it, and those extra memory references are what make a miss costly,
as OSTEP's chapter on TLBs explains. When the cache is indexed by physical
address, translation finishes before the cache lookup starts, so the average
gains a term in front:

**Average = TLB time + TLB miss rate × walk time + data access time.**

With an illustrative 0.5 ns lookup, 1% of accesses missing and a 40 ns walk,
the 3.4 ns hierarchy above becomes 0.5 + 0.01 × 40 + 3.4 = 4.3 ns. Real designs
work hard to overlap the lookup with the cache access, which this model does
not show.

A TLB holds few entries, so what it can translate without missing is its
**reach**: entries × page size. Predict before opening the trace: a cold TLB
with four entries and LRU replacement serves a loop that reads one address in
each of three pages, then the same three pages again. Another loop does the
same with five pages. Which accesses of each second pass hit?

With three pages, the second pass hits every time: all three translations fit.
With five, every access misses. Each new page evicts the least recently used
entry, which is always the page the loop needs next, so LRU loses the whole
second pass. OSTEP calls touching more pages in a short time than the TLB holds
exceeding its coverage. Larger pages raise the reach without more entries, which
is why programs with large, randomly accessed data use them.

</details>

## A TLB miss is not a page fault

Three different events can slow a load, and diagnostic counters report them
separately:

- A **data-cache miss** fetches a line from the next level; the translation was
  already known.
- A **TLB miss** looks up a translation in the page table; the data may still be
  in a cache.
- A **page fault** is an exception the operating system handles: a missing
  mapping, a page not yet allocated, or an access its permissions forbid. Some
  faults need storage I/O; others do not.

The [operating systems subject](/subjects/operating-systems-runtime-internals/)
plans the page tables and faults behind this lookup.

## Two-minute recap

- Average access time = hit time + miss rate × additional miss penalty; check
  whether a quoted penalty is additional or total.
- Each level's penalty is the next level's average, so local miss rates
  multiply into the share of loads that reach memory.
- A rare trip to memory can dominate the average.
- Translation adds a TLB lookup, and a page-table walk on each TLB miss; reach
  is entries × page size.
- TLB misses, cache misses and page faults are different events.
- Averages ignore overlap: measure elapsed time on the target system.
