## An instruction is a contract encoded in bits

In [program execution](/learn/computer-architecture-execution/how-computers-execute-programs/),
we traced operations with names such as set and add. Hardware does not receive
those words as prose. An **instruction set architecture**, or ISA, gives bit
patterns defined effects on the machine's visible state.

Think of an instruction as a form with fields: which action, which destination,
which inputs. Both sender and receiver must agree on the form. The analogy stops
at flexibility: hardware accepts the formats it implements; a convenient new
mnemonic does not create a new machine operation.

The ISA defines the software-visible contract. A **microarchitecture** is one
implementation of it. Different implementations can have different pipelines,
cache sizes and execution resources while supporting the same instructions.
Conversely, a processor may implement optional extensions that another processor
in the same family lacks. An executable's target requirements therefore matter.

## Read operands before reading mnemonics

An **opcode** identifies an operation. Its **operands** identify the values or
locations used by the operation. Three common operand forms are:

| Form      | Meaning                               | Important distinction                                             |
| --------- | ------------------------------------- | ----------------------------------------------------------------- |
| Immediate | A constant carried in the instruction | Its range depends on the available encoding bits                  |
| Register  | A named architectural register        | The name identifies storage, not a source-language variable       |
| Memory    | Data accessed through an address      | The address and the contents at that address are different values |

A **load** transfers a value from memory into a register; a **store** transfers a
value from a register into memory. Arithmetic may then operate on registers.
Supported combinations differ by ISA: a load/store ISA separates memory access
from most arithmetic, while other instruction sets allow some arithmetic
instructions to read memory operands directly. Neither label alone establishes
performance.

**Predict:** if a register contains address 1000, does adding one to the register
necessarily change the value stored at address 1000? No. It changes the register's
bit pattern. A separate operation that writes through the address would change
memory. Confusing these two jobs is a common source of pointer mistakes.

The masks extract each field without including adjacent bits. Validation before

the opcode field. Silently masking it down to zero would change the requested
operation instead of reporting the invalid input.

The tests round-trip all 8192 valid instructions: two opcodes, 16 registers, and
256 immediates. They also check invalid field ranges and reserved opcodes.
Round-tripping protects the invariant that decoding an encoded valid operation
recovers exactly its three fields.

## Registers are scarce names for active values

Architectural registers are directly named by instructions. General-purpose
registers can hold arithmetic values or addresses. Special registers track
control or other machine state, although the exact categories and access rules
vary by ISA. A register does not inherently know that its bits came from a
variable named price or pointer.

A compiler assigns values to registers based on where each value is needed. Two
values whose useful lifetimes do not overlap can reuse the same register. If too
many values need registers together, the compiler may **spill** some into memory
and load them later. Such accesses can increase work, but the outcome depends on
the complete generated code and memory behavior.

<Callout title="Count instructions with their effects">
  One source expression may become several machine instructions, or disappear
  after optimization. One machine instruction may also require several internal
  operations. A shorter instruction sequence is evidence to investigate, not a
  guarantee of a faster program.
</Callout>

## A calling convention connects separate functions

The ISA alone does not say which register a language's first argument must use.
A **calling convention** makes that agreement: how arguments and results travel,
which registers survive a call, and how stack state is maintained. A broader
**application binary interface**, or ABI, covers additional binary agreements
such as data layout and object-file interfaces.

The [stack lesson](/learn/computer-architecture-execution/stack-and-heap/) traces caller/callee preservation and return state using the shared native example.

## Costs and limits of this decoder

Encoding or decoding one fixed 16-bit word uses a bounded number of operations,
so it takes O(1) time and O(1) auxiliary space in the lab's word-operation model.
That statement describes these TypeScript helpers. It does not measure a real
processor's decode latency or prove anything about a complete compiler.

Real formats must trade off register selection, immediate range, instruction
length and room for more operations. A larger immediate may require another
instruction or a different encoding. Variable-length encodings can improve code
density but add decoding considerations. Choose a concrete target before
reasoning about those trade-offs quantitatively.

## Read the real load, add and store

The shared native lab compiles `bump` for Linux x86-64 using the System V ABI.
Its tested input is an unsigned 32-bit value 7. The pointer arrives in the
64-bit register RDI; the returned 32-bit value uses EAX. These names belong to
this target, not the illustrative 16-bit format above.

Read the three data instructions in order: `movl (%rdi), %eax` loads four bytes
at the address in RDI; `addl $1, %eax` changes only the register; `movl %eax, (%rdi)`
stores four bytes back. With RDI = 1000, memory[1000..1003] changes from 7 to 8
only at the store. For an indexed operand, a base of 1000 plus index 3 scaled by
4 addresses byte 1012. Loading the address and loading its contents are distinct.

`ret` resumes the caller using the saved return address. The security landing
instruction `endbr64` and assembler directives do not implement the increment.
A 64-bit pointer, a 32-bit operand, and a variable-length x86 instruction are
three different widths. Sign-extending byte `0xff` preserves −1 as `0xffff`;
zero-extension preserves unsigned 255 as `0x00ff`.

**Transfer task:** start with memory value 41 and base 2000. Predict memory and
EAX after each data instruction, then locate the first mistake in a trace that
changes memory immediately after the addition. The correct final value is 42;
the premature memory change is the error. See the compilation lesson to reproduce
the actual artifact; the model decoder is not an x86 emulator.

## Two-minute recap

- The ISA defines visible behavior; the microarchitecture implements it.
- An opcode chooses an operation; operand fields choose inputs or destinations.
- An immediate value, a register value, and memory addressed by that value are distinct.
- Fixed-width fields have a finite budget, and invalid values must not spill into neighbors.
- Compilers reuse registers and may spill values; variables have no permanent register identity.
- Correct function calls require the platform's calling convention as well as valid instructions.
