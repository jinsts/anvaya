## A byte needs an interpretation

A sensor sends the byte `11111111`. Is the reading 255, -1, part of a text
character, or eight independent flags? The bits alone cannot answer. The sender
and receiver must agree on width, signedness, byte order and encoding.

Think of a label reading `10`: the value changes if the label is decimal or
binary. That analogy explains interpretation, but computer formats also specify
what happens when a value cannot fit. A wrong format can turn a valid packet into
an impossible measurement without changing a single bit.

The [instruction lesson](/learn/computer-architecture-execution/cpu-registers-and-instructions/)
introduced registers and operations. Here we establish what their operands mean.
We use eight-bit bytes and byte-addressed memory throughout; other machine models
must state their own units.

## Unsigned and signed integers

A binary digit at position k, counting from zero at the right, contributes 2 to
the power k. Thus `00001101` means 8 + 4 + 1 = 13. Hexadecimal groups four bits
per digit: the same byte is `0x0d`. Hexadecimal is a display convention, not a
separate kind of storage.

An unsigned w-bit integer ranges from 0 through 2 to the power w minus 1.
For **two's complement**, the highest bit has negative weight. With eight bits,
`10000000` is -128 and `01111111` is 127. To interpret an unsigned bit pattern u
whose high bit is set, subtract 256. Therefore `11111111` is 255 - 256 = -1.
The signed range is asymmetric because zero occupies one of the nonnegative
patterns.

A fixed-width modular adder retains the low w result bits. For eight bits:

<div className="table-scroll" tabIndex={0} role="region" aria-label="Unsigned carry and signed overflow examples">

| Inputs interpreted as unsigned | Retained byte | Unsigned carry | Signed interpretation                          |
| ------------------------------ | ------------- | -------------- | ---------------------------------------------- |
| 127 + 1                        | `10000000`    | No             | 127 + 1 cannot fit; retained result means -128 |
| 255 + 1                        | `00000000`    | Yes            | -1 + 1 = 0 fits                                |

</div>

**Carry** reports a result beyond the unsigned range. **Signed overflow** reports
a signed mathematical result beyond the signed range. Neither condition implies
the other.

## Read and manipulate individual bits

A **mask** selects positions: bitwise AND keeps a position only when both inputs
have a one there. To read one bit, shift its position down to position zero and
mask off every other bit. The lab's `bitAt` applies this to a checked byte and a
position from zero through seven.

A logical right shift fills the vacated high positions with zeros. An arithmetic
right shift repeats the sign bit, preserving the sign of a two's complement
operand. JavaScript spells these number operations `>>>` and `>>`, respectively;
their 32-bit conversions still apply. A shift is not a universal replacement for
division across languages, signed values and rounding rules.

In binary addition, each column receives the two operand bits and any carry
from the previous column. Keeping only the result bit and propagating the carry
explains why a sum may require an extra position. Choose the output width before
deciding whether to retain, report or reject that extra bit.

## Floating point buys range with limited precision

IEEE 754 binary floating point separates a sign, an exponent and a significand.
The exponent scales a finite collection of significand bits. Large magnitudes
therefore have wider gaps between adjacent representable values; the format does
not retain the same decimal resolution everywhere.

Binary64 has 53 bits of significand precision for normal values. Fractions such
as one tenth repeat in binary, so storing them requires rounding. The tested
example produces `0.30000000000000004` when adding the stored approximations of
0.1 and 0.2. Changing the display to one decimal place does not change the stored
value.

The format also has subnormal numbers, signed zeros, infinities and NaN. NaN is
not equal to itself under ordinary numeric equality. Do not use one universal
small constant as a cure for every comparison: tolerance should account for
magnitude, accumulated error and the application's decision boundary. Exact
currency totals may suit integer minor units, provided the scale, rounding and
maximum range are specified.

## Byte order and record layout

A 16-bit value `0x1234` has a high byte `0x12` and a low byte `0x34`.
**Little-endian** order stores the low byte first, at the lower address;
**big-endian** stores the high byte first. Byte order does not reverse the bits
inside each byte. Network and file formats should name an order explicitly
rather than inherit the sender's host order.

**Alignment** constrains the address at which a field begins. Suppose our chosen
record rules give one-byte fields alignment one and a four-byte field alignment
four. A byte, integer, byte record then has offsets 0, 4 and 8. Three bytes of
interior padding and three of trailing padding make its total size 12. Trailing
padding allows the next record in an array to begin suitably aligned.

These are explicit model inputs. Real ABI rules decide field alignment, record
alignment and exceptions. Reordering the fields can reduce padding, but can also
change a public binary interface. Serializing raw records risks exposing padding
and depending on host rules; encode protocol fields deliberately.

## Text has several different lengths

Unicode assigns **code points** to characters and other text elements. UTF-8
encodes each **Unicode scalar value** (a code point outside the reserved surrogate
range) into one to four bytes. UTF-16 uses one or two 16-bit code units for the
same values. JavaScript strings expose UTF-16 code units.
For example, the supplementary code point in `🙂` uses two code units and four
UTF-8 bytes.

A visible grapheme can combine several code points, as with a letter and a
combining accent. Thus bytes, code units, code points and visible text units are
four different counts. A network byte limit and a cursor moving over visible
text require different operations. Decide which boundary the task actually asks
for before indexing or truncating text.

## Two-minute recap

- Width and interpretation give a bit pattern meaning; two's complement has an
  asymmetric signed range.
- Unsigned carry and signed overflow answer different questions.
- Floating point represents a finite set of values, so rounding and scale matter.
- Byte order, alignment and padding belong to explicit format or ABI rules.
- Count text in bytes, code units, code points or graphemes according to the task.
- Test the smallest, largest and just-outside representable values.
