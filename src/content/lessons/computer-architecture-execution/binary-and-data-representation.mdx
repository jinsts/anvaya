## A byte needs an interpretation

A sensor sends the byte `11111111`. Is the reading 255, −1, or eight separate
flags? The bits alone cannot say. Sender and receiver must agree on the
**width** and on the **interpretation**, and on what happens when a result does
not fit. A wrong guess turns a valid packet into an impossible measurement
without changing a single bit.

Think of a label reading `10`: its value changes with the base you assume. The
analogy stops at overflow. A fixed-width register also decides what to keep
when a result needs more bits than it has, and two programs can make different
decisions about the same bits.

The [execution lesson](/learn/computer-architecture-execution/how-computers-execute-programs/)
traced changing machine state. Here we fix what an integer's bits mean. Two
later pages extend the same idea to [floating-point numbers](/learn/computer-architecture-execution/floating-point-representation/)
and to [text, byte order and record layout](/learn/computer-architecture-execution/text-encoding-and-memory-layout/).

## Unsigned and two's complement

A binary digit at position k, counting from zero at the right, weighs 2ᵏ, so
`00001101` means 8 + 4 + 1 = 13. Hexadecimal writes four bits per digit, so the
same byte is `0x0d`. Hexadecimal is a way to write bits, not a different kind
of storage.

An unsigned w-bit integer ranges from 0 to 2ʷ − 1. **Two's complement** gives
the top bit a negative weight, −2ʷ⁻¹, and keeps every other weight. With eight
bits, `10000000` is −128 and `01111111` is 127; to read a pattern whose top bit
is set, subtract 2ʷ from its unsigned value, so `11111111` is 255 − 256 = −1.
The range is asymmetric because zero takes one of the non-negative patterns.

<TwosComplementWheel />

The wheel shows why one adder serves both readings. Adding 1 always steps one
position clockwise and keeps the low w bits. The unsigned reading jumps only at
the top, from 15 back to 0; the signed reading jumps only at the bottom, from 7
to −8. The same hardware addition is correct for both readings except where it
crosses that reading's break.

## Carry and overflow answer different questions

**Carry** reports that the unsigned sum needed one more bit. **Signed
overflow** reports that the signed sum fell outside −2ʷ⁻¹ to 2ʷ⁻¹ − 1, which
happens exactly when both operands have the same sign and the kept result has
the other sign. Neither implies the other:

<CarryOverflowGrid />

The adder does not know which reading the program intends. x86-64 therefore
records both conditions, as the carry flag CF and the overflow flag OF, and a
later instruction chooses which one to test.

## Widen and shift without changing the meaning

Widening a value adds high bits. **Zero extension** fills them with 0, which
preserves the unsigned value. **Sign extension** copies the top bit, which
preserves the two's complement value: `0xff` becomes `0x00ff`, 255, or `0xffff`,
−1. Converting buffer bytes with the wrong extension turns small negative
readings into large positive ones.

Right shifts make the same choice. A **logical** shift fills vacated high bits
with zeros; an **arithmetic** shift copies the sign bit, so a negative value
stays negative. In JavaScript these are `>>>` and `>>`, applied after the
operand is converted to 32 bits. An arithmetic shift by k divides by 2ᵏ but
rounds toward −∞: a byte holding −7 shifted right by 1 gives −4, while C's
signed division `-7 / 2` rounds toward zero and gives −3.

## Read and change single bits

A **mask** selects positions. `x & mask` keeps only the masked bits, `x | mask`
sets them, `x & ~mask` clears them and `x ^ mask` flips them. To read bit k,
shift it down to position 0 and mask with 1: `(x >>> k) & 1`. The lab's
`bitAt` does exactly this for a checked byte.

## Two-minute recap

- Width and interpretation give a bit pattern meaning; two's complement gives
  the top bit weight −2ʷ⁻¹, so its range is asymmetric.
- One adder serves both readings: carry marks the unsigned break, signed
  overflow the signed one, and either can occur without the other.
- Zero extension preserves unsigned values; sign extension preserves signed
  values. Logical and arithmetic shifts make the same choice.
- Masks read, set, clear and flip single bits.
- Language rules, such as undefined signed overflow in C, are separate from
  what the hardware does.
