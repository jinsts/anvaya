interviewQuestions:
  - prompt: What is SIMD, and what kind of loop benefits from it?
    answer: >-
      Single instruction, multiple data: one instruction applies the same
      operation to several values packed in a wide register, such as four 32-bit
      integers in a 16-byte register. It suits loops that do the same work on
      every element of contiguous arrays, with no dependence between
      iterations, such as adding two arrays. It does not help when the
      iterations depend on each other, when the data is scattered, or when the
      loop is already limited by memory bandwidth.
  - prompt: Why might a compiler refuse to vectorize a loop?
    answer: >-
      It must prove that doing several iterations at once gives the same
      result. Possible overlap between input and output arrays, a dependence
      from one iteration to the next, calls or control flow it cannot
      transform, and floating-point reductions, whose result depends on the
      order of additions, all block it. Compilers can report their decisions,
      for example GCC's `-fopt-info-vec`, so check the report rather than
      assume.
    followUps:
      - What does `restrict` promise the compiler in C?
  - prompt: Why can a vectorized floating-point sum give a different answer from a scalar loop?
    answer: >-
      A vectorized sum keeps several partial sums, one per lane, and combines
      them at the end. That reorders the additions, and floating-point addition
      rounds after every step, so the order changes the result. GCC therefore
      vectorizes such a sum only under options such as `-fassociative-math`
      that allow reordering. Integer addition, which does not round, can be
      reordered freely.
  - prompt: What is the remainder loop in vectorized code for?
    answer: >-
      A vector loop processes a fixed number of elements per iteration, so when
      the array length is not a multiple of that width, a few elements are left
      over. A scalar remainder loop, or a narrower vector loop, handles them.
      For short arrays the remainder can be most of the work, so vectorization
      helps most on long arrays.

## Same work, wider registers

Adding two arrays of a million integers is a million identical additions with no
dependence between them. A scalar loop does them one per iteration. Processors
also have **vector registers**, 16 bytes or wider, and instructions that apply
one operation to every value packed in them: **SIMD**, single instruction,
multiple data. One instruction can add four pairs of 32-bit integers.

Think of a cashier who rings up four identical items with one scan and a
quantity, instead of scanning each. The analogy stops at irregular work: SIMD
helps only when every lane does exactly the same operation on neighboring data.

## A vector loop and its remainder

<LanesDiagram />

A compiler that **vectorizes** a loop processes one vector's worth of elements
per iteration and finishes whatever is left over in a scalar **remainder loop**.
For n elements and w lanes there are ⌊n ÷ w⌋ vector iterations and n mod w
remainder elements. Before running the stepper, predict both for a length and
width you choose.

The loop at `.L4` loads 16 bytes of `a` and of `b` with `movdqu`, adds four pairs
at once with `paddd`, stores 16 bytes with `movups`, and advances its offset by 16. After it, `testb $3` checks whether n is a multiple of four, and `.L6` is the
scalar remainder loop. Short arrays, of three or fewer elements, jump straight
to the remainder. Compiled with `-fno-tree-vectorize`, the same function has
only the scalar loop.

The `restrict` qualifiers in the source matter: they promise that `out` does
not overlap `a` or `b`. Without that promise, writing four elements of `out` at
once could change inputs that later lanes still need, and the compiler would
have to check for overlap at run time or not vectorize at all.

It loads four values per iteration but still adds them one at a time, with the

## When vectors do not help

- **Dependences:** if iteration i needs iteration i − 1's result, as in a prefix
  sum, lanes cannot work independently without restructuring the algorithm.
- **Scattered data:** gathering elements from unrelated addresses costs much of
  the gain; contiguous arrays, such as a structure of arrays, vectorize best.
- **Memory bandwidth:** when a loop is already waiting on memory, as in the
  [DRAM lesson](/learn/computer-architecture-execution/dram-ssd-and-disks/)'s
  large working sets, doing arithmetic faster does not speed it up.
- **Short loops:** the remainder and setup can outweigh the vector part.

## Two-minute recap

- SIMD applies one instruction to every lane of a wide register: four 32-bit
  values in 16 bytes.
- A vectorized loop does ⌊n ÷ w⌋ vector iterations and a scalar remainder of
  n mod w elements.
- Read the listing: packed instructions such as `paddd` and `addps`, a stride of
  one vector, and a remainder loop after it.
- Compilers vectorize only what they can prove equivalent: `restrict` rules out
  overlap, and float sums need permission to reorder.
- Vectors do not help dependent, scattered, short or memory-bound loops.
